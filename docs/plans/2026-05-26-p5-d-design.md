# P5-d — 0.5.0 同步功能 GA：GUI 登录 + keychain + 设备管理 + watchdog + 真机验证

> 2026-05-26 起草 v1 → v2 评审 → **v3 锁定 2026-05-26**。
>
> v3 关键修正：
> - **生产路径完全不用 spawn env 传 token**（Node ChildProcess env 复制后不可撤）。daemon 始终 unauthenticated 启动，GUI main 通过 HTTP `/sync/session` 注入，唯一路径。env token 只留 dev/test，需双 env gate
> - `/sync/session` 是 **replace 语义**：stopBackgroundHandles → 清旧 session → set 新 → restart，不是简单 ensureBackgroundHandles（后者见 `bridge-lifecycle.ts:185` 会因已有 bridge 跳过）
> - **watchdog 不依赖 `close() → onError`** 触发重连，直接 `unsubscribe → mark offline → scheduleReconnect()`
> - skybridge 0.1.2 `onFrame` **必须能看到 `:ok` 等 comment block**，SDK parser 当前忽略，需显式暴露 raw block
> - `/sync/session` 成功立刻持久化 device/workspace 到 sqlite local_metadata，不等首次 sync
> - **sync_cursor key 必须按 workspace 隔离**（当前 `endpoint` 只用 server URL，切号 / 同 server 换 workspace 会复用旧 `pulled_seq`）
> - GUI main 写 toml = **完整 session metadata**（server / auth / device / workspace 四段）+ **atomic write**
> - SDK 表 `DELETE /auth/logout` 笔误改 `POST`
> - 新增 §3.7：进程 / 内存 / 文件 / 日志卫生（含 `OWL_GUI_PARENT_PID` 子进程探测、atomic toml、自有 route/error logger 不带 body）
> - owl-cli 0.5.0 提前到 owl 0.5.0 发版前（compat 版本，sync run/status 走 daemon，sync login/config show 提示"请用 GUI"）
> - skybridge 0.1.2 走 **next → latest 短过渡**：Phase 4 SDK / dual e2e smoke 通过后 **Phase 5 即 promote latest**，不等本地全链路或 24h soak
> - Phase 4 验收改为 "SDK / daemon fixture smoke"，真正 GUI login 真机 smoke 在 Phase 14 阿里云 dogfood
> - logout 只清 identity（local_metadata 白名单字段），**不**清 sync_cursor；cursor 跨 workspace 隔离纯靠 `syncEndpointKey(serverUrl, workspaceId)`，同 workspace 重新 login 续推 pulled_seq

承接 0.4.2 ship（P5-a/b/c 内部 GA）。本阶段不收集新增产品需求；scope 在 2026-05-26 三轮对话钉死并经 server endpoint audit + SDK audit + 两轮技术评审校验。

## 1. 背景

### 1.1 0.4.2 已实现 / 0.5.0 要补的差距

0.4.2 同步主路径走通（push / pull / apply / SSE / 定时 / 退避 / 冲突记录 / token 不泄漏路 C），13/13 dual e2e + 957/957 单元绿。但 0.4.2 是 **"in-process 测试 GA"**，对外仍有 5 类缺：

1. GUI 没有登录 / 切换账号入口
2. token 仍明文存盘
3. 设备管理只能 SSH server 查表
4. SSE 没有 idle watchdog
5. 完全没在公网 server 跑过

### 1.2 0.5.0 一句话

**daemon 始终 unauthenticated 启动；GUI main 持有 safeStorage、完成远端 login + 完整 session metadata 写 toml + HTTP `/sync/session` 注入 daemon；daemon 收到 session 才拉起 SSE + scheduler。skybridge bump 0.1.2 additive。阿里云 server 24h+ 真机 soak 通过后发 0.5.0。**

### 1.3 必证条件（0.5.0 发版门槛）

1. **GUI login**：用户在 settings 填 server URL + email + password → **GUI main** 完成 login + device register + workspace ensure → safeStorage 加密 token → atomic 写 toml（含 server/auth/device/workspace 四段）→ HTTP `/sync/session` 推 daemon → daemon `persistSkybridgeIds` + 拉起 bridge + scheduler
2. **GUI logout / 切换账号**：GUI main 调远端 `/auth/logout` → HTTP `/sync/logout-local` 通知 daemon **stopBackgroundHandles + 清 ctx.skybridgeSession + 清 sqlite identity 白名单字段** → GUI main 清 toml；切换账号 = logout + 重新 login
3. **token 不落明文 / 不残留进程 env**：toml 无明文 `[auth].token`；**生产路径 daemon 进程从不通过 env 接收 token**；dev 双 env gate（`OWL_DAEMON_DEV_TOKEN` + `OWL_ALLOW_INSECURE_DEV_TOKEN=1`）才接受，启动后两个 env 都 delete
4. **设备管理 GUI**：可看当前 user 名下所有 device，正确标识"当前设备"（依赖 `/sync/session` 立刻 `persistSkybridgeIds`）
5. **SSE idle watchdog**：≥ 60s 内没收到任何 frame（含 `:ok` comment）→ daemon 主动 `unsubscribe + mark offline + scheduleReconnect`，不依赖 `close() → onError`
6. **真机 soak 全绿**：双 Mac → 阿里云 server，**≥ 24h** 连续运行，期间必须覆盖：(a) 网络 drop ≥ 1 次 (b) server restart ≥ 1 次 (c) GUI restart ≥ 1 次 (d) 至少 1 次跨设备冲突。出 P1/P2 或准备扩大测试则延 48h
7. **基线测试**：单元约 977/977，dual e2e 13/13 跑在 **skybridge 0.1.2** 上，`just check` 4 guards 全过

### 1.4 不做 / 推 0.6+

- `/auth/register` HTTP endpoint
- token TTL + `/auth/refresh`
- 多 app account 统一抽象层
- pair code 流程
- 设备 **撤销** 功能（server 无 endpoint，**0.5.0 UI 完全不提及 revoke**，不放 placeholder）
- attachments / snapshots 通道
- 反向代理 / HTTPS / 公网安全加固

## 2. Audit 结论

### 2.1 Server endpoint（v0.1.1，零改动）

| 我们需要 | server | 备注 |
|---------|--------|------|
| `POST /auth/login` | ✅ | email+password → token |

| `POST /auth/refresh` | ❌ | 不在 scope |
| `POST /auth/register` | ❌ admin CLI | 不在 scope |
| Revoke other device | ❌ | view-only |

### 2.2 skybridge-client SDK（v0.1.1，需 bump 0.1.2 additive）

| 我们需要 | v0.1.1 | v0.1.2 |
|---------|--------|--------|
| `login(...)` / `createSkybridgeClient(...)` | ✅ | 不动 |
| `client.registerDevice / ensureWorkspace / push / pull` | ✅ | 不动 |
| `client.subscribeEvents({ onChange })` | ✅（仅 change frame） | **加 `onFrame?`，覆盖任何 raw block 含 `:ok` comment（**parser 当前忽略 comment block，需扩出 raw event callback**）** |
| `client.logout()` | ❌ | **新增**：`POST /auth/logout` |
| `client.listDevices()` | ❌ | **新增**：`GET /devices` |

**bump 策略**（**先 next，再 promote latest**）：

1. skybridge 仓本地实现 + tests → `pnpm test` 全绿

3. owl 把依赖 pin/bump 到 `^0.1.2`（指定 `next` tag 装）→ 跑 dual e2e + SDK / daemon fixture smoke
4. 全绿后 `npm dist-tag add @orpheus-aviary/skybridge-client@0.1.2 latest`（同包 promote，不重发）
5. **不等本地全链路 / 24h soak 才 promote**——Phase 4 SDK + dual e2e 通过即在 Phase 5 promote

## 3. 范围（硬钉，v3）

### 3.1 主线一：GUI 登录 / 登出 / 切换账号

**核心架构**：

```
登录:
  renderer Settings → IPC sync:login
       ↓
  GUI main sync-auth.ts
       ├ fetch <server>/auth/login         拿 token (函数局部)
       ├ fetch <server>/devices/register   拿 device
       ├ fetch <server>/workspaces         找/建 workspace
       ├ safeStorage.encryptString(token)
       ├ atomic 写 toml (server + auth + device + workspace 四段)
       ├ HTTP POST 127.0.0.1:<daemon>/sync/session  传完整 session
       └ token 局部变量出作用域 → GC
  daemon /sync/session handler (replace 语义):
       ├ if ctx.skybridgeSession 已有 → stopBackgroundHandles(ctx) + 清旧 ctx.skybridgeSession
       ├ set new ctx.skybridgeSession from request body
       ├ persistSkybridgeIds (立刻写 sqlite local_metadata)
       └ startBackgroundHandles (SSE + scheduler，已含 fresh ctx)

启动:
  daemon 无条件 unauthenticated 启动 (env 完全不参与)
  GUI main 读 toml encrypted_token 是否存在
       ├ 不在 → daemon 保持 unauthenticated，等用户 login
       └ 在   → safeStorage 解密 token (局部变量) → 重组 session → POST /sync/session 注入
                                                                       ↑
                                                          走和 login 完全相同的 replace 路径

登出:
  GUI main sync-auth.ts logout()
       ├ fetch <server>/auth/logout   (吃异常: 远端不通也继续)
       ├ HTTP POST 127.0.0.1:<daemon>/sync/logout-local
       │      ↓
       │   daemon: stopBackgroundHandles + 清 ctx.skybridgeSession + clearSyncIdentity(sqlite)
       └ atomic 写 toml (清 auth/device/workspace 三段，保留 server.url + sync.interval_min)
```

#### 3.1.1 daemon 端改动

新增 / 改造：

- **新增 `POST /sync/session`**（body: `{ token, user_id, email, server_url, device: {id,name,...}, workspace: {id,name,...} }`）
  - **Replace 语义**：先 `stopBackgroundHandles(ctx)` + 清 `ctx.skybridgeSession`，再 set 新值
  - 立刻持久化 device id / workspace id 到 sqlite `local_metadata`（沿用现有 `persistSkybridgeIds(sqlite, deviceId, workspaceId)`，不等首次 sync）
  - 再调 `startBackgroundHandles(ctx)`（SSE bridge + scheduler）
  - 仅 `127.0.0.1` 监听
  - **该 endpoint 的 body 不进任何 owl 自有 logger**（route handler 内不调 `log.info(req.body)` / `log.debug(body)`；pino redact 兜底，详见 §3.7.5）
- **新增 `POST /sync/logout-local`**
  - `stopBackgroundHandles(ctx)` + 清 `ctx.skybridgeSession` → null
  - 调 `clearSyncIdentity(sqlite)` 白名单清字段（见 §3.6）
  - 不调远端 `/auth/logout`（GUI main 负责）
  - 不动 toml（GUI main 负责）
- **删除现有 `/sync/login`**（`packages/daemon/src/sync/manual.ts:281` 那段），retire
- **daemon 启动 token 来源（v3 关键变化）**
  - **生产路径**：daemon 启动**完全不读任何 env 中的 token**；启动后立即进入 unauthenticated；等 `/sync/session` 注入
  - **dev/test 路径**：仅当**同时**存在 `OWL_DAEMON_DEV_TOKEN=<plaintext>` **和** `OWL_ALLOW_INSECURE_DEV_TOKEN=1` 时才接受 env token 作为冷启动 session；接受后立刻 `delete process.env.OWL_DAEMON_DEV_TOKEN` + `delete process.env.OWL_ALLOW_INSECURE_DEV_TOKEN`
  - prod 构建时（`NODE_ENV=production` 或 packaged GUI 拉起）即使两个 env 都设置也硬拒绝并 panic
- daemon config 类型彻底删 auth 段的认证字段；保留可选 `[auth].user_id` / `[auth].email` 作为展示来源（daemon 不当认证用）
- daemon **必须从环境变量 `OWL_GUI_PARENT_PID` 读取父进程 PID**（GUI spawn 时传入），启动一个低频（10s）`process.kill(pid, 0)` 探测；父进程消失 → `stopBackgroundHandles` + 清 session → 进入 unauthenticated 状态（不退出进程，留 daemon 仍可被 CLI 调用读非 sync 数据）

#### 3.1.2 GUI main 端改动（新增 `packages/gui/src/main/sync-auth.ts`）

实现：

- `loginAndOpenSession({ serverUrl, email, password })`
  - 调远端 `POST /auth/login` 拿明文 token（**局部变量**，不挂任何长期对象）
  - 串行 `POST /devices/register` + `GET/POST /workspaces`
  - `safeStorage.encryptString(token)` → base64
  - **atomic 写 toml**（见 §3.7.4）。`skybridge_config.toml` 内容**只含同步身份四段**，sync interval 等运行参数在 owl 自己的 config 里，不进 skybridge 配置：
    ```toml
    [server]
    url = "<server_url>"

    [auth]
    encrypted_token = "<base64>"
    user_id         = "<id>"
    email           = "<email>"

    [device]
    id   = "<device_id>"
    name = "<hostname>"

    [workspace]
    id   = "<workspace_id>"
    name = "<workspace_name>"
    ```
  - HTTP `POST 127.0.0.1:<daemon>/sync/session` body 重组完整 session（明文 token 在此 HTTP 短暂出现，localhost 仅）
  - 函数返回前 token 局部变量出作用域；不挂任何 module-level 缓存
  - 失败 unwind：拿到 token 但后续步骤失败 → fetch `/auth/logout` revoke + 不写 toml
- `logout()`
  - fetch 远端 `/auth/logout`（吃异常）
  - HTTP `/sync/logout-local`
  - atomic 写 toml 清 `[auth]` + `[device]` + `[workspace]` 三段（`[server].url` 保留，方便下次 login 默认填）
- `restoreSessionOnStartup()`（GUI main 启动时调）
  - 读 toml `[auth].encrypted_token`，无则 noop（daemon 保持 unauthenticated）
  - 有则 `safeStorage.decryptString` → 局部变量 → 与 toml 中 device/workspace 重组 → HTTP `/sync/session` 推 daemon
- `spawnDaemonProcess(...)`（改造现有 `packages/gui/src/main/daemon.ts:46`）
  - **绝不**通过 env 传 token
  - spawn 时传 `OWL_GUI_PARENT_PID=<process.pid>` env
  - daemon ready 信号（监听 port 已就绪）后再调 `restoreSessionOnStartup`

### 3.4 主线四：SSE idle watchdog

依赖 skybridge-client 0.1.2 的 `onFrame` callback（必须覆盖 `:ok` 等 comment block）。

**client 改动**（`packages/daemon/src/sync/sse-bridge.ts`）：

- 订阅时传 `onFrame: () => { state.lastFrameAt = Date.now(); }`
- 每 30s 跑 watchdog tick，检查 `now - lastFrameAt > 60s`
- **触发路径（v3 关键修正）**：
  ```
  watchdog tick 命中阈值
    → log kind:'sse-watchdog' status:'closed-by-idle'
    → unsubscribe / abort 当前 SSE stream
    → mark state.online = false
    → 调 onErrorHook（与 fetch-SSE 静默 abort 路径一致语义）
    → scheduleReconnect()  ← 直接调度，不依赖 close() → onError 自动触发
  ```
- 阈值 60s 不小于 server `PING_INTERVAL_MS (25s) × 2`
- **timer 生命周期**：watchdog timer 注册在 `SseBridge.state` 上；`SseBridge.stop()` **必须 clearInterval**；reconnect 路径先 stop 旧 watchdog 再 start 新的（不叠加）

**daemon.log 关键字**：`kind:'sse-watchdog'`，含 `started` / `closed-by-idle` / `next-check-at` / `stopped`

**单测**（fake EventSource + onFrame 推空 frame）：

- 持续推 `:ok` → watchdog 永不触发
- 停 frame 65s → watchdog 命中 → reconnect schedule
- watchdog close 后重连 → 新 watchdog 启动，旧 timer 已清
- `SseBridge.stop()` 后断言 timer 清空 + 没 pending callback
- reconnect 后断言只有 1 个 active watchdog

**真机验证**：阿里云 server 连上后 `iptables -A INPUT -p tcp --sport 8443 -j DROP`，60s+ 见 `sse-watchdog closed-by-idle`，解除 iptables 后 SSE 自动重连。

### 3.6 主线六：logout 清理 sqlite identity + sync cursor 按 workspace 隔离

#### 3.6.1 `local_metadata` 白名单清理

避免切号后本地新变更带旧 device id。

**白名单删除**：

- `skybridge_device_id`
- `skybridge_workspace_id`

- 显式 enumerate 上述 3 key 调 DELETE
- **不**用 `LIKE 'skybridge_%'` 前缀清，避免误删未来非身份字段
- 单测：插 3 个 key + 1 个 `skybridge_future_unrelated` → `clearSyncIdentity` 后前 3 个被删，第 4 个保留

#### 3.6.2 `sync_cursor` key 按 workspace 隔离（v3 新增）

**问题**：当前 `sync_cursor.endpoint` 列只用 server URL（见 `packages/core/src/sync/engine.ts:115` / `:165-177` / `:809`，及 `packages/daemon/src/sync/manual.ts:374`）。切换账号或同 server 换 workspace 后，新 workspace 复用旧 `pulled_seq` → 漏拉新 workspace 的历史变更。

**修法（key 隔离，不动 logout 路径）**：

- 新增 helper `syncEndpointKey(serverUrl: string, workspaceId: string): string`，统一返回 `serverUrl + "#" + workspaceId`（schema 不变，仍是 TEXT column；不动 migration，0.4.2 用户切到 0.5.0 后该列内容自然 rewrite）
- engine.ts 中 `upsertSyncCursor` / `readSyncCursor` / `runSync` 全部经 `syncEndpointKey()` 取 key，禁止散在各处用裸 `serverUrl`
- daemon manual.ts:374 同步改造
- **logout 不动 `sync_cursor` 任何行**——隔离纯靠 key，同 workspace 重 login 续推 pulled_seq 是预期行为（避免漏拉远端在登出期间产生的 change）

**单测**：

- workspace A pulled_seq=100 → 切到 workspace B → runSync 时 readCursor 返回 0，不复用 A 的 100
- workspace A pulled_seq=100 → logout → 重新 login 同一 workspace → readCursor 仍返回 100（cursor 连续）
- 两 workspace 同时进 sync_cursor 表，互不影响

### 3.7 主线七（新增）：进程 / 内存 / 文件 / 日志卫生

#### 3.7.1 token 内存

- **daemon** 只保留单一当前 session token（`ctx.skybridgeSession.token`）；`/sync/session` replace 时旧 session 必须置 null + 显式 nullify token 字段（依赖 GC）
- **GUI main** `loginAndOpenSession` / `restoreSessionOnStartup` 的 token 只挂局部变量，函数返回前不挂任何 module-level 缓存；POST `/sync/session` 完成后立即不可达
- 单测：`/sync/session` 调用 2 次后 `ctx.skybridgeSession.token === 第二次 token`，与第一次不同；旧 bridge 实例已 stop

#### 3.7.2 timer

- watchdog timer 在 `SseBridge.stop()` 强制清（见 §3.4）
- 任何 setInterval / setTimeout 在 lifecycle 结束时显式 clear，禁止"先 unref 就行"思路
- 测试：`stop()` 后断言 `state.watchdogTimer === null`；reconnect 后 active timer 数恒等 1

#### 3.7.3 进程链

- GUI spawn daemon 时 env 传 `OWL_GUI_PARENT_PID=<process.pid>`
- daemon 启动后注册 10s `process.kill(parentPid, 0)` 探测；父进程消失（ESRCH）→ `stopBackgroundHandles` + 清 session → unauthenticated（保留进程供 CLI 调用读非 sync）
- 单测：mock parent kill → daemon 5s 内 stop SSE bridge

#### 3.7.4 toml atomic 写

- GUI main 写 toml：
  1. 写 `<config>.tmp`（同目录，permissions 0600）
  2. fsync
  3. rename `<config>.tmp` → `<config>`
- 启动时清理 stale `.tmp`（启动时存在则删，可能上次 crash 留下）
- `.tmp` 内容也加密（绝不在 `.tmp` 阶段写明文 token）
- 单测：mock crash 在 fsync 后 rename 前 → 启动后 `.tmp` 被清，主 config 完整

#### 3.7.5 日志 redact

> 现状勘误：Fastify 自身的 request/response logger 在 `packages/daemon/src/server.ts:15` 已经关闭，所以**不需要也无法**在 route 层 "disable fastify body log"。真正要防的是 owl 自有的 route handler 日志、error handler 日志、以及 pino structured fields 兜底。

- 现有 pino redact 路径补：
  - `token` / `body.token` / `req.body.token` / `request.body.token`
  - `encrypted_token`（保险起见，理论上不在 log 流但加无害）
- `/sync/session` route handler 内**禁止**调 `log.info(req.body)` / `log.debug(body)` / 任何含 body 字段的 structured log；只 log `{ kind: 'sync-session', op: 'replace', user_id, workspace_id }` 这种非敏感摘要
- error handler（global onError）若包含 body 字段，必须经 pino redact 过滤后再输出
- 守卫脚本：现有 `scripts/check-token-not-templated.sh` 不变；新增 `scripts/check-session-body-not-logged.sh`，grep `/sync/session` handler 文件中是否出现 `log.*\(.*body.*\)` / `log.*\(.*token.*\)` 模式
