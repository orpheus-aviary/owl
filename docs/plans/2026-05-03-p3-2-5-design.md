## 2. 功能 ① — 未保存 tab 退出弹窗

### 2.1 当前状态

- `editor-store.ts:44` 已有 `dirty: boolean` per tab；`updateContent`/`updateTags` 会按 content/tags baseline 对比自动维护。
- `main/index.ts:50` 已有 `before-quit` handler：preventDefault → stopDaemon → app.quit()。
- macOS 红叉只触发 `close` 事件 → `onWindowClose` 隐藏窗口，**不**走 `before-quit`。所以真正退出路径是 Cmd+Q / 菜单 / Windows 非 macOS 红叉 / dock Quit。
- **现状：退出时 dirty tab 静默丢失**（还没弹）。

### 2.2 目标 UX

1. 用户触发退出 →
2. 主进程 `before-quit` 拦截（已有逻辑先 stop daemon）→
3. 先走 **unsaved check IPC**：询问渲染进程是否有 dirty tab；
4. 渲染进程如有 N 个 dirty tab → 依次弹 N 个对话框（Word/VSCode 风格）：
   > 是否保存 **<tab title>** 的更改？
   > [保存] [不保存] [取消]
5. 用户对每个 tab 选：
   - **保存** → 调用 `requestSaveOrConflict(noteId)`（见 §2.3 / §2.4，处理 AI 冲突路径）；成功继续下一个，失败则保持模态显示通用错误文案（`saveNote` 返回 `boolean`，没有具体 err.message 可用），让用户再选 "不保存" 或 "取消"；
   - **不保存** → 仅把 `'skip'` 写进 `decisions` map、进入下一个；**不** mutate tab 内容或 dirty 标记；
   - **取消** → 整个退出流程中止，app 保持运行，所有 tab 原状；
6. 所有 tab 处理完（queue 走到底）→ 渲染进程 `respond(true)`；主进程走原来的 stopDaemon + app.quit() 尾巴。

### 2.3 边界决策

| 场景 | 行为 | 原因 |
|---|---|---|
| 全部 tab 已保存 | 跳过整个弹窗流程，直接退出 | 无感流程 |
| Draft tab（`isDraft: true`） | 弹同一个对话框；保存 = 创建新笔记（`saveNote` 走 POST 分支） | 复用现成路径 |
| AI pending tab 带 conflict | **严格方案**：保存走 `requestSaveOrConflict`；若返回 `false`（意味 `conflictPrompt` 已被 set）→ 渲染进程 `quit.respond(false)`、关闭 UnsavedTabsDialog，顶层既有 `<ConflictDialog>` 接管。用户解决冲突后自行再 Cmd+Q。 | `saveNote` 在 `pendingAiUpdate` 存在时会直接 PATCH AI payload，会吞掉 `pre_stage_*` 里的本地未保存内容。必须走 conflict 路径才是正确语义 |
| 保存失败（网络/daemon 挂） | 弹窗内显示**通用错误文案** `保存失败，请稍后重试或选择 "不保存"`（`saveNote` / `requestSaveOrConflict` 只返回 `boolean`，拿不到 err.message；3.2.5 不为此改 store 契约）；选项变为 [重试] [不保存] [取消] | 不让错误吞噬数据，也不为错误 UX 拉扯 store 改造 |
| Renderer 无响应 | 主进程 `askRendererAboutUnsaved` 10s 超时 → 视作 `proceed: true` + `log.warn`，继续退出 | 避免 Cmd+Q 永久卡死，用户只能 Force Quit |
| 用户在 UnsavedTabsDialog 开着时再 Cmd+Q | `before-quit` 用 `pendingQuitCheck` flag 挡住重入；二次事件直接 preventDefault 无动作 | 防止 `pendingQuitResolve` 被覆盖、Promise 泄漏 |
| macOS 窗口隐藏状态下 Cmd+Q（从 dock） | `askRendererAboutUnsaved` 前检测 `win.isVisible()`，隐藏则 `win.show()` + `win.focus()` | 否则 dialog 在隐藏窗口里看不到 |
| macOS 红叉（仅隐藏） | 不触发弹窗（现有行为不变） | 窗口隐藏 ≠ 退出 |
| Cmd+W 关闭窗口（macOS） | 不触发弹窗（走 `close`，app 不退出） | 同上 |
| Windows / Linux 红叉 | `window-all-closed` → `app.quit()` → `before-quit` → 走弹窗 | 平台惯例 |
| stopDaemon 失败 | 现有逻辑就是 log + 继续 quit，弹窗流程不影响 | 不劣化 |

### 2.4 实现拆分

**主进程 (`packages/gui/src/main/index.ts`)**：

```ts
let isQuitting = false;
let pendingQuitCheck = false;
let pendingQuitResolve: ((proceed: boolean) => void) | null = null;

const QUIT_CHECK_TIMEOUT_MS = 10_000;

app.on('before-quit', async (event) => {
  if (isQuitting) return;
  event.preventDefault();
  if (pendingQuitCheck) return; // 已在询问渲染进程，二次 Cmd+Q no-op
  pendingQuitCheck = true;
  try {
    const proceed = await askRendererAboutUnsaved();
    if (!proceed) return; // 用户取消，app 继续运行
    isQuitting = true;
    try {
      await stopDaemonGracefully();
    } catch (err) {
      console.error('Error stopping daemon on quit:', err);
    }
    app.quit();
  } finally {
    pendingQuitCheck = false;
  }
});

function askRendererAboutUnsaved(): Promise<boolean> {
  const win = BrowserWindow.getAllWindows()[0];
  if (!win || win.isDestroyed()) return Promise.resolve(true); // 没窗口不 block
  if (!win.isVisible()) {
    win.show();
    win.focus();
  }
  return new Promise((resolve) => {
    let settled = false;
    const settle = (proceed: boolean) => {
      if (settled) return;
      settled = true;
      pendingQuitResolve = null;
      resolve(proceed);
    };
    pendingQuitResolve = settle;
    win.webContents.send('quit:check-unsaved');
    setTimeout(() => {
      if (!settled) {
        console.warn('quit:check-unsaved timed out; proceeding without confirmation');
        settle(true);
      }
    }, QUIT_CHECK_TIMEOUT_MS);
  });
}

ipcMain.on('quit:response', (_e, proceed: boolean) => {
  pendingQuitResolve?.(proceed);
});
```

**Preload (`packages/gui/src/preload/index.ts`)**：

```ts
quit: {
  onCheckUnsaved: (cb: () => void): (() => void) => {
    const listener = () => cb();
    ipcRenderer.on('quit:check-unsaved', listener);
    return () => ipcRenderer.off('quit:check-unsaved', listener);
  },
  respond: (proceed: boolean): void => {
    ipcRenderer.send('quit:response', proceed);
  },
}
```

**Store 补充 (`packages/gui/src/renderer/src/stores/editor-store.ts`)**：

在 `EditorState` interface 增：

```ts
hasUnsavedTabs: () => boolean;
getUnsavedTabs: () => TabState[];
```

实现过滤条件 **`dirty || isDraft || pendingAiUpdate !== null`** —— 和 `saveNote` 内 L340 的 guard 条件保持一致（`if (!tab.dirty && !tab.pendingAiUpdate && !tab.isDraft) return true`）。三者任一成立都表示 "有未提交状态，需要走一次 save"。

**组件新增 `packages/gui/src/renderer/src/components/UnsavedTabsDialog.tsx`**：

- 状态机：`{ queue: TabState[]; currentIdx: number; decisions: Map<noteId, 'save' | 'skip'>; saving: boolean; error: string | null }`
- Hook 在 `MainApp.tsx` 顶层挂一次，监听 `window.owlAPI.quit.onCheckUnsaved`。**注意**：MainApp 只在 `startupMode.mode === 'normal'` 时被挂载；Migration 流程下 renderer 跑的是 `MigrationDialog`，没有这个 hook。为避免 Cmd+Q 白等 10s 再触发超时兜底：
  - **选 A（首选）**：`main/index.ts` 记录 `currentStartupMode`，在 `before-quit` 早分支：`if (currentStartupMode !== 'normal') { 直接放过，stopDaemon + app.quit() }`，完全跳过 IPC 询问。Migration 流程下没有 dirty tab 概念，也不应被未保存弹窗阻塞。
  - **选 B（备用）**：`MigrationDialog.tsx` 挂一个极简 listener，收到 `quit:check-unsaved` 立刻 `respond(true)`。保留 IPC 对称性，但多一处要维护。
  - **3.2.5 采用选 A**。改动点：`main/index.ts` 把 `precheck.mode` 暂存到模块级 `currentStartupMode`，`before-quit` 早分支判断；IPC 路径只在 normal 模式下触发。
- 收到事件 → 读 `editorStore.getUnsavedTabs()`：
  - 空 → 直接 `respond(true)`；
  - 非空 → 进入依次处理状态机；
- 使用 shadcn `AlertDialog`（项目已有）。UI：标题 `未保存的更改`，描述 `是否保存 "${tab.title}" 的更改？`，三按钮并排。
- **"不保存" 仅记录意图，不 mutate store**：把 `tab.noteId → 'skip'` 写进 `decisions` map，然后 `currentIdx++`。如果后续用户在别的 tab 选 "取消"，之前选过 "不保存" 的 tab 仍然保留 dirty 内容在内存里 —— app 不退出，数据还在。真正的 "丢弃" 是通过 `app.quit()` 后进程结束隐式发生的。
- **保存分支**：
  1. `const ok = await requestSaveOrConflict(tab.noteId);`
  2. `ok === true` → `decisions.set(tab.noteId, 'save')`、进入下一个；
  3. `ok === false` 且 `editorStore.conflictPrompt !== null` → 说明触发了 AI 冲突：立即 `respond(false)`、关闭本对话框、清空 queue。顶层 `<ConflictDialog>` 接管显示。用户解冲突完成后自己再 Cmd+Q。
  4. `ok === false` 且 `conflictPrompt === null` → 真 save 失败（API/网络）：显示通用文案 `保存失败，请稍后重试或选择 "不保存"`（不解包具体 err，store 契约只返 boolean）、按钮切换为 [重试] [不保存] [取消]、留在当前 tab。
- **取消分支**：`respond(false)`、清空 queue、关闭对话框。不 mutate tab 任何内容。
- 全部 tab 处理完（queue 走到底）→ `respond(true)`。

## 3. 功能 ② — `owl skill export`

### 3.1 CLI 命令签名

```
owl skill export [--output <path>]
```

- 无子命令扩展计划；预留 `owl skill` 作为未来 group（例如 `owl skill list`）。
- 默认输出：`~/orpheus-aviary-nest/owl/owl-skill.md`（`paths.owlDir()` 已导出）。
- `--output <path>`：
  - 是目录 → 写入 `<path>/owl-skill.md`；
  - 是文件路径 → 按路径直接写（可非 `.md` 后缀，不校验）；
  - 相对路径 → 按当前 `process.cwd()` 解析。
- 文件存在时覆盖（复用全局 `--overwrite` 语义？—— 这里不走 CAS，没有冲突概念，直接覆盖即可，不需要 flag）。
- **`dirname(outputPath)` 不存在时自动 `mkdir -p`**（`fs.mkdir(dir, { recursive: true })`）。纯 CLI 首次运行时 `~/orpheus-aviary-nest/owl/` 可能尚未被任何组件创建过，不能让这种默认路径写文件失败。

### 3.2 stdout 输出

命令成功后打印（human-readable，不走 `--json` 包装，因为目的是给人看然后复制）：

```
✓ owl skill 已导出到:
  /Users/jay/orpheus-aviary-nest/owl/owl-skill.md

下一步：把下面这段提示词完整粘贴给你正在使用的 AI 助手（Claude Code / Cursor / Cline / 其他），
由它根据你当前 agent 的 skill 规范把文件安装到全局或项目级 skill 目录：

────────────────────────────────────────────────────────────
请读取 /Users/jay/orpheus-aviary-nest/owl/owl-skill.md，把它作为一个 skill 安装到当前 AI agent
的全局 skill 目录（如果不确定全局路径，就装到当前项目级目录）。请按照当前 agent 的 skill 规范调整
前置元数据（例如 Claude Code 的 YAML frontmatter、Cursor 的 .mdc globs），然后告诉我最终装到了
哪里、以及如何验证触发正常。
────────────────────────────────────────────────────────────
```

- **此命令是 owl CLI 里第一个 "默认 human" 的刻意例外**。普通 note 命令（search/get/create/...）默认 JSON、输出一律走 `writeResult`；`owl skill export` 的产物是文件，stdout 的核心价值是把提示词复制给 agent，所以翻转默认。
- **输出模式三分支**（互斥）：
  | 组合 | 行为 |
  |---|---|
  | 无 flag | **human 模式**：按上面样式打印到 stdout |
  | `--json` | **JSON 模式**：stdout 为扁平 `{"path": "...", "prompt": "..."}`（与其他命令一样**不**包 `{success, data}`），`writeResult(payload)` 即可 |
  | `--human` | 同无 flag（显式） |
  | `--json --human` | **报 `USAGE_ERROR`**（exit 2），互斥 |
- `--pretty` 在 JSON 模式下仍按全局约定生效（2-space indent）；human 模式忽略。
- stdout：成功摘要 + 提示词；stderr：无 progress（本操作是瞬时的）。

### 3.3 Skill 内容结构

```markdown

# owl — notes CLI for agents

owl 是猫头鹰笔记的命令行接口。daemon 运行时走 HTTP（与 GUI 共享数据），daemon 不运行时直连 SQLite (WAL)。

## Invocation
Run via the Bash tool: `owl <command> [flags]`.

**Output shape**: each command prints its own business JSON directly to stdout — there is **no** `{success, data, message}` wrapper. Examples:
- `owl search` → `{ total, items, limit, page }`
- `owl get <id>` → note object `{ id, content, tags, folder_id, created_at, updated_at, ... }`
- `owl create` / `owl edit` → saved note object

On error: `{ "error": { "code": "...", "message": "...", "details"?: {...} } }` is written to **stderr**, and the process exits with a non-zero code.

**Common flags** (apply to note commands unless stated): `--pretty` (2-space indent), `--ndjson` (one JSON object per line for list output), `--id-only` (ids only, one per line). Note commands default to **JSON on stdout** — there is no universal `--human` mode for them. The only command that defaults to human-readable output is `owl skill export`, which writes a markdown file and prints a copy-pasteable instruction prompt; pass `--json` to that specific command if you want `{ "path": "...", "prompt": "..." }` instead.

## Commands

## Exit codes
| Code | Meaning |
|---|---|
| 0 | success (includes `doctor` reporting `warn`) |
| 1 | ordinary failure (`NOTE_NOT_FOUND`, `DB_BUSY`, `HTTP_ERROR`, `UNKNOWN`) |
| 2 | usage / argument error (`USAGE_ERROR`, `INVALID_JSON_INPUT`, `INVALID_TAG`) |
| 3 | environment / config problem (`CONFIG_NOT_FOUND`, `doctor` fail) |
| 4 | daemon unavailable (HTTP mode required but daemon not running) |
| 5 | conflict (`VERSION_MISMATCH`, `DAEMON_RUNNING_BLOCKED`, `MIGRATION_BUSY`, ...) |
| 130 | cancelled (SIGINT, y/N prompt answered N) |
```

**实现**：

- `apps/cli/src/commands/skill.ts` 新建，导出 `runSkillExport(flags, deps)`。
- Skill markdown 内容由 `apps/cli/src/commands/skill-template.ts` 导出的 **`renderOwlSkillTemplate({ version })`** 函数生成：
  - 参数：`{ version: string }`（由 `buildProgram()` 的 `.version()` 注入，避免硬编码）；
  - 返回：完整 markdown 字符串；
  - 内部保持 `name` / `description` / `Invocation` / exit code 表等块为常量拼接，命令列表可基于一份常量数组渲染，便于测试遍历。
- 理由：
  - 避免 tsup 打包时处理 static 资源的配置复杂度；
  - 模板 ~5KB 量级，嵌入 JS 完全可接受；
  - 测试可以单独断言 frontmatter、每个命令出现、exit code 数值正确，而不需要做 markdown 解析；
  - 未来加 `--format cursor|agents-md` 时，传 `format` 参数切分支即可。

### 3.4 注册到 CLI

`apps/cli/src/index.ts`：

```ts
const skill = program.command('skill').description('skill file operations for AI agents');
skill
  .command('export')
  .description('export owl CLI skill markdown (for Claude Code / Cursor / other agents)')
  .option('--output <path>', 'output path (file or dir); default ~/orpheus-aviary-nest/owl/owl-skill.md')
  .action(async (flags: Record<string, unknown>, cmd: Command) => {
    const opts = cmd.optsWithGlobals() as GlobalOptions;
    // skill export 是 CLI 里 "默认 human" 的例外：仅在显式 --json 时输出 JSON。
    // 显式 --json + --human 并存 → USAGE_ERROR (见 §3.2)
    if (opts.json === true && opts.human === true) {
      throw new CliError('USAGE_ERROR', '--json and --human are mutually exclusive');
    }
    await runSkillExport(
      {
        ...flags,
        pretty: opts.pretty === true,
        json: opts.json === true,
        human: opts.human === true,
      },
      { streams },
    );
  });
```

## 4. 功能 ③ — GUI 检测 CLI

### 4.1 检测机制

- **平台**：macOS / Linux 执行 `which owl`；Windows 执行 `where.exe owl`。
- **位置**：仅在**主进程**执行。用 `node:child_process` 的 `execFile`（不走 shell，避免注入和 PATH 副作用；便于单测 mock），显式传 `{ env: { ...process.env, PATH: expandedPath } }` 控制查找范围。
- **PATH fallback（macOS Finder/dock 启动场景关键）**：Electron 从 Finder/dock 启动时 `process.env.PATH` 通常仅为 `/usr/bin:/bin:/usr/sbin:/sbin`，不含 `/usr/local/bin`、`/opt/homebrew/bin`、nvm/asdf shims、`~/.npm-global/bin` 等，会导致 `which owl` 在用户明明装了 CLI 时仍返回 `not found`。策略：
  1. 先按当前 `process.env.PATH` 跑 `which owl`，命中即返回；
  2. 未命中时，构造一个**扩展 PATH**（拼接用户 login shell 常见安装目录 + 现有 PATH），重跑一次：
     - macOS / Linux 扩展集：`/usr/local/bin`, `/opt/homebrew/bin` (Apple Silicon Homebrew), `/opt/homebrew/sbin`, `~/.npm-global/bin`, `~/.volta/bin`, `~/.nvm/versions/node/*/bin`（glob 展开最新一个即可）, `~/.asdf/shims`, `~/.cargo/bin`, `/usr/local/opt/node/bin`；
     - Windows 扩展集：`%AppData%\npm`, `%LocalAppData%\Programs\Python\*\Scripts`（保守列常见 npm-global 路径，pkg 分发的 CLI 不走 Python，这里只是对齐处理思路）；
  3. 可选强化（不在 3.2.5 范围）：spawn 一个 login shell `sh -lc 'which owl'` 读 PATH。好处是拿到用户 shell rc 注入的所有路径，代价是冷启动慢 ~100-300ms 且要处理 shell 不同。**3.2.5 不做，记为后续优化**。
- **失败判定**：exit code ≠ 0 或 stdout 为空 → 未安装。判定前必须先尝试扩展 PATH，否则 false negative。
- **版本**：若找到 → 再 exec `owl --version`（超时 2s，failures 不 block）获取版本字符串。版本探测也用扩展后的 PATH。
- **缓存**：每次用户进入 `Settings → 高级` 时重新检测（不做跨进程缓存；检测本身 <100ms，带扩展 PATH 后 <300ms）。

```ts
export async function detectCli(): Promise<CliDetectResult> {
  const cmd = process.platform === 'win32' ? 'where.exe' : 'which';
  // 1) 先用当前 PATH 跑一次
  let found = await tryFind(cmd, 'owl', process.env.PATH);
  // 2) 未命中 → 拼扩展 PATH 再试一次（解决 Finder/dock 启动的窄 PATH）
  if (!found) {
    const expanded = expandPath(process.env.PATH ?? '');
    if (expanded !== process.env.PATH) {
      found = await tryFind(cmd, 'owl', expanded);
    }
  }
  if (!found) return { installed: false };
  // 3) 版本探测（2s timeout，失败不 block）
  const version = await tryVersion(found.path, found.pathEnv);
  return { installed: true, path: found.path, ...(version ? { version } : {}) };
}

function expandPath(current: string): string {
  const home = os.homedir();
  const extras = process.platform === 'win32'
    ? [path.join(process.env.APPDATA ?? '', 'npm')]
    : [
        '/usr/local/bin',
        '/opt/homebrew/bin',
        '/opt/homebrew/sbin',
        path.join(home, '.npm-global/bin'),
        path.join(home, '.volta/bin'),
        path.join(home, '.asdf/shims'),
        path.join(home, '.cargo/bin'),
        // nvm: 取最新版本的 bin。实现走 numeric semver 比较，避免字符串排序
        // 把 v9.x 排到 v22.x 之后这种坑。
        ...findLatestNvmBin(home),
      ];
  const sep = process.platform === 'win32' ? ';' : ':';
  const existing = new Set(current.split(sep).filter(Boolean));
  const added = extras.filter((p) => p && !existing.has(p));
  return [current, ...added].filter(Boolean).join(sep);
}
```

`main/index.ts` 注册：`ipcMain.handle('cli:detect', detectCli)`。
