## 2. 核心架构决策

### 2.1 daemon 在 packaged app 里的启动方式

**Electron-as-Node spawn**：把现有 `spawn('node', [cliPath, 'daemon'])` 改为

```ts
spawn(process.execPath, [cliPath, 'daemon'], {
  env: { ...process.env, ELECTRON_RUN_AS_NODE: '1' },
  detached: true,
  stdio: 'ignore',
})
```

关键点：必须 `...process.env` 展开父环境，否则 daemon 子进程会失去 `HOME` / `PATH` / 代理与 API key 相关环境变量（如 `HTTPS_PROXY`、`ANTHROPIC_API_KEY` 等），导致 AI 请求、日志目录定位、better-sqlite3 加载全部失败。

- packaged app 不依赖用户机器有 `node`
- daemon 继续独立子进程、继续写 `daemon.pid` 做单例
- GUI 和 CLI 都只负责 "发现 → 拉起 → 连接"，daemon 自己管生命周期

### 2.2 退出语义（修订 P3 §2.2）

| 动作 | 行为 |
|---|---|
| 红叉关窗 | 隐藏窗口，app 在 dock 保留，daemon 继续跑，点 dock 图标复现窗口 |
| Cmd+Q / 菜单 Quit | **完全退出**：如果 daemon 是 GUI 本次启动时自己拉起的（`daemonStartedByGui=true`），先停它（读 `daemon.pid` → SIGTERM → 等 3s → SIGKILL 兜底），再退 GUI。若 daemon 启动前已在跑（GUI 只是连过去），则只退 GUI，不碰 daemon。 |
| CLI 场景需要 daemon 常驻 | 未来 P3.2 CLI 设计时再定命令名与启动语义；0.2.0 scope 内无 CLI，GUI 退出只影响它自己拉起的 daemon |

这与 Docker Desktop / OrbStack 等"GUI + 本地 daemon"类软件保持一致（单门模式）。

**对 P3 主计划文档的修订**：不在本文档里改，在 §7 列出需要同步修订的 §2.2 条目，写 plan 时一起落。

### 2.3 better-sqlite3 原生模块

- `packages/gui/package.json` 里 `"postinstall": "electron-builder install-app-deps"`，`pnpm install` 时自动针对 Electron ABI 重编所有 native 模块（`install-app-deps` 内部封装了 `@electron/rebuild`，不需要独立引入）
- `asarUnpack: '**/node_modules/better-sqlite3/**'` 保证 `.node` 文件运行时能被加载

### 2.4 workspace 依赖如何进 dmg

`@owl/daemon` 和 `@owl/core` 都是 workspace 包。electron-vite build 只 bundle renderer 和 main 的 TS；`@owl/daemon` 的 dist 不会被 inline 进 main bundle（因为 `spawn` 是运行时 import，不是 static import）。

**策略：默认路径 A（electron-builder 默认行为），smoke 1 验证，失败才 pivot 到路径 B**

- **路径 A**：只在 `files` 里保留最小必要的排除项，信任 electron-builder 默认扫 `packages/gui/package.json` 的 `dependencies` 字段并把 `node_modules/**` 里 @owl/daemon、@owl/core 以及它们的传递依赖（fastify、commander、better-sqlite3、pino、drizzle-orm 等）一起打进 asar。pnpm workspace symlink 也会被 electron-builder 跟进展开。
- **路径 B（fallback）**：新增 `packages/gui/scripts/bundle-daemon.mjs`，用 `pnpm deploy` / `pnpm isolate` 产出 daemon 的 production closure，复制到 `packages/gui/resources/daemon/`，`daemon.ts` prod 分支读 `resources/daemon/cli.js`。

**失败判据**：smoke 1 如果出现 `@owl/daemon/cli` resolve 失败 或传递依赖 resolve 失败（fastify / better-sqlite3 等），先加 `.npmrc: node-linker=hoisted` 专供 GUI 包；仍不行再切路径 B。每一步独立 commit，方便回退。

### 2.5 图标资源

- 源图：`packages/gui/resources/owl-logo-original.png`（1254×1254 RGBA，从 repo 根目录搬进来）
- 生成产物：`packages/gui/resources/icon.icns`
- 生成脚本：`packages/gui/scripts/build-icons.mjs`，用 macOS 自带 `sips` + `iconutil`，无新 deps
- 产物 gitignore，不 commit 二进制；`just package` 前置跑 `build:icons`
- 名称稳定：源 PNG 可以后期替换内容但名字不改，避免 electron-builder 配置跟着改

### 3.3 package.json 片段

```jsonc
{
  "version": "0.2.0",
  "scripts": {
    "postinstall": "electron-builder install-app-deps",
    "build:icons": "node scripts/build-icons.mjs",
    "build:deps": "pnpm -F @owl/core build && pnpm -F @owl/daemon build",
    "package": "pnpm build:deps && pnpm build:icons && electron-vite build && electron-builder --mac --arm64 --config electron-builder.yml"
  },
  "devDependencies": {
    "electron-builder": "^25.1.8"
  }

```

注：
- `@electron/rebuild` 不单独列，`electron-builder install-app-deps` 内部已封装；避免双路径触发 rebuild。
- `build:deps` 显式前置确保 `@owl/core` 和 `@owl/daemon` 的 `dist/` 最新。它们的 `package.json` exports 指向 `dist/`（`@owl/daemon/cli` → `dist/cli.js`），干净 checkout 或 dist 过期时 electron-builder 会打包成功但运行时 resolve 失败，所以 package 脚本必须自包含依赖构建。
- `just package` 直接调 `pnpm --filter @owl/gui package`，不额外叠一层 build-core/build-daemon，避免双源头。

### 3.4 退出逻辑改造（`src/main/index.ts`）

```
let isQuitting = false;

function createWindow() {
  const win = new BrowserWindow({ /* ... */ });

  // 红叉：非退出流程时拦截，隐藏而不销毁，保留 renderer 内存状态
  win.on('close', (event) => {
    if (!isQuitting && process.platform === 'darwin') {
      event.preventDefault();
      win.hide();
    }
  });
}

app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') {
    app.quit();
  }
  // macOS: 不退，保留 dock 图标
});

app.on('activate', () => {
  // 优先显示已存在的隐藏窗口，不存在才 createWindow
  const existing = BrowserWindow.getAllWindows();
  if (existing.length > 0) {
    existing[0].show();
  } else {
    createWindow();
  }
});

app.on('before-quit', async (event) => {
  if (isQuitting) return;
  event.preventDefault();
  isQuitting = true;
  await stopDaemonGracefully();  // 读 pid → SIGTERM → 3s 超时 SIGKILL，只在 daemonStartedByGui=true 时执行
  app.quit();
});
```

**关键点**：
- `win.on('close')` 里拦截红叉并 `hide()`，renderer state（未提交 draft、AI 对话 scroll 位置、zustand store）全部保留
- `activate` 优先 `show()` 现有窗口；只有无窗口时才 `createWindow()` 重建
- `isQuitting` 标记让 `before-quit` 和 `close` 协同，避免死锁

### 3.5 daemon spawn 改造（`src/main/daemon.ts`）

- 新增模块级标记 `let daemonStartedByGui = false`
- `spawnDaemon()` 返回 `ChildProcess | null`（spawn 本身失败时 null）
- 启动时逻辑：
  ```
  if (await checkDaemon()) {
    // daemon 已经在跑（用户手动或其他流程），GUI 只连接，不负责生命周期
    daemonStartedByGui = false;
  } else {
    const child = spawnDaemon();
    if (!child) {
      // @owl/daemon/cli resolve 失败 / spawn 系统调用失败
      daemonStartedByGui = false;
      logger.error('Failed to spawn daemon');
    } else {
      // 轮询 /status，200 之前都算未就绪；最长等 10s
      const ready = await waitForDaemonReady({ timeoutMs: 10_000 });
      if (ready) {
        daemonStartedByGui = true;   // 只有真正起来了才算 GUI 拥有
      } else {
        daemonStartedByGui = false;  // spawn 成功但 /status 没绿，视为未拥有，留给下次重试
        logger.error('Daemon spawn returned but /status never responded');
      }
    }
  }
  ```
  - 这样任何失败路径（resolve 失败 / spawn 失败 / /status 超时）都不会让 Cmd+Q 误去 kill 一个不是自己拉起的 pid
- `spawnDaemon()` 本身改为 Electron-as-Node：
  - dev：`process.execPath` 是 `electron` 二进制，加 env 后作为 node 运行
  - prod：同样
  - **env 必须 `...process.env` 展开父环境**，只追加 `ELECTRON_RUN_AS_NODE: '1'`；否则 daemon 子进程丢 `HOME` / `PATH` / `HTTPS_PROXY` / `ANTHROPIC_API_KEY` 等关键变量（详见 §2.1）
  - 用 `esmRequire.resolve('@owl/daemon/cli')` 拿 CLI 路径；try/catch 包住返回 null
- 新增 `stopDaemonGracefully()`：
  - **首先检查 `daemonStartedByGui`，为 false 时直接 return，不碰别人的 daemon**
  - 读 `~/orpheus-aviary-nest/owl/daemon.pid`（来自 `packages/core/src/config/paths.ts` 的 `pidPath()`）
  - `process.kill(pid, 'SIGTERM')`
  - 轮询 `/status` 或 `process.kill(pid, 0)` 直到退出或 3s 超时
  - 超时后 `process.kill(pid, 'SIGKILL')`

- 同一个 dmg：GUI 发 `GET /notes?limit=1` 能返 200

### Smoke 3 — 退出语义

- Cmd+Q（`daemonStartedByGui=true` 路径）→ `daemon.pid` 消失、`ps aux | grep owl` 无残留
- Cmd+Q（`daemonStartedByGui=false` 路径）→ 手动先 `pnpm -F @owl/daemon run dev` 起一个 daemon，然后启 GUI 再 Cmd+Q，确认外部 daemon 仍在跑、`daemon.pid` 保留

每个 smoke 失败单独 commit 修复，不混打。
