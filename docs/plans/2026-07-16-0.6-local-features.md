## 2. ① 本地同步状态指示（S–M）

### 2.1 现状（两 bug）
1. **误导**：未注册/本地 profile daemon `state:'idle'` → 侧栏 `SyncStatusBar.tsx:76` → `STATE_INFO['idle']` = 灰点+「已同步」（纯本地却称已备份到云）。
   > **⚠️ 实施修正（2026-07-21 手测）**：原判据「本地 = `server_url:null`」**是错的**。真实 dev 环境里 `skybridge_config.toml` 残留 `[server].url`（如 `127.0.0.1:8443`）会让 `server_url` **非空**，但 `device_id`/`workspace_id` 仍 null（未注册）→ 掉进账号分支误显「已同步」。**正确判据 = 设备+工作区是否已注册**（`readSyncStatus` 的 `device_id!=null && workspace_id!=null`，`manual.ts:329-330`；GET/SSE 两路径都带这两字段，broadcaster `initialSnapshot` 复制自 `readSyncStatus`）。见 §2.2 `isAccountSnapshot`。
2. **null 非单义**：`snapshot===null` 既是冷启动，也是 `sync-status.fetch()` 失败后**永久 null**（`sync-status.ts:107-121` 吞异常）。简单渲染「…」→ daemon 不可达时永显「…」+ aria 不可访问。

### 2.2 sync-status store 加 `probeStatus` 三态 + bar 四分支
**store**：`probeStatus: 'pending' | 'ok' | 'unreachable'`（初始 `pending`）。`fetch()` 成功→`ok`；catch→`unreachable`（不再静默）；SSE `setSnapshot`→隐含 `ok`。

**bar 派生**（`SyncStatusBar.tsx`）：
```ts
const LOCAL_INFO   = { label: '本地',  dotClass: 'border border-muted-foreground',    spin: false };  // D1: hollow ring, 无新图标
const PENDING_INFO = { label: '连接中', dotClass: 'border border-muted-foreground/50', spin: false };
const DOWN_INFO    = { label: '未连接', dotClass: 'bg-amber-500',                       spin: false };
// ⚠️ 判据修正：账号 = 已注册（device+workspace），非 server_url≠null（§2.1）。
const isAccountSnapshot = (s) => s.device_id !== null && s.workspace_id !== null;
const info =
  probeStatus === 'unreachable' ? DOWN_INFO            // D12: 掉线压过陈旧 snapshot（否则永显旧「本地/已同步」）
  : snapshot != null
    ? (isAccountSnapshot(snapshot) ? STATE_INFO[snapshot.state] : LOCAL_INFO)
  : PENDING_INFO;
```
`aria-label` 用具体 `info.label`（全部可访问）。popover：`!isAccountSnapshot`→「本地独立工作区」（且**不显手动同步按钮**——对未注册工作区只会一直报错）；`unreachable`→顶部补「daemon 未响应，正在重试」。hollow ring = 渲染处圆点去 `bg-*`、由 `dotClass` 给 `border`。
> **D12（运行中掉线，P2-8）**：`probeStatus==='unreachable'` **压过非空 snapshot** —— 否则首次成功后 daemon 进程掉线会**继续显示旧「本地/已同步」**。注意与账号态 `offline`（daemon 在、够不到同步服务器）语义不同：`unreachable` = 够不到 **daemon 本身**。

### 2.3 ③ 关联
`sync-status.reset()` 须把 `probeStatus` 重置回 `pending`。

### 2.4 ⭐ 状态恢复：SSE hello 重探（v3 新增，修 review「永久未连接」）
`handleDaemonEvent` 对 keep-alive `'hello'` 帧 no-op（`events-subscriber-core.ts:54`）。若首次 `/sync/status` 失败（`probeStatus:'unreachable'`），之后 SSE 重连只发 `hello`、GUI 忽略 → **状态永停「未连接」**。
**改**：`EventsSubscriber` 识别 `'hello'`（连接建立信号）→ 调 `useSyncStatus.getState().fetch()` 重探（`hello` 不入 `EVENT_TYPES` 白名单，单独走一条 onConnected 分支，不改 `OwlEvent` union）。这样每次 SSE 建连都刷新一次状态，`unreachable` 能自愈。
**+ 掉线检测（D12）用 exactly-once `onDisconnect`（P2-a；v3.3 明确契约）**：`subscribeSse` 的旧 `onError` **只在 `connectOnce` 抛错**时触发；SSE body **正常结束 / 无 body 时静默重连**、不触发 → 单靠它仍显陈旧 snapshot。→ **shared `subscribeSse` 加 exactly-once `onDisconnect({error, clean, usedToken})`**，每个连接周期结束**恰好一次**：抛错→`{error, clean:false}`；正常 EOF / 无 body→`{error:null, clean:true}`；**abort（`signal.aborted`）不触发**。**`usedToken` = 本次 `connectOnce` 开始时从认证源捕获的裸 token**（每次重连都重读 authHeaders → 必须逐次捕获，不能用订阅创建时的 token）。**移除对 `onError` 用于重探/401 的依赖**（避免 error 时 onError+onDisconnect 双触发 → 双探针 / 401 双失活；`onError` 若留仅作 warn 日志）。`EventsSubscriber` 接 `onDisconnect → useSyncStatus.getState().fetch()` 重探。**故 ① 触及含 shared**；测试覆盖 error/EOF/no-body/abort 四类。
**并发重探按 generation 分区 single-flight（P2-a；v3.3）**：bootstrap / hello / 连续断线会并发调 `fetch()` → `sync-status` 探针存 `{gen, promise}`，**仅复用同 gen 的在途请求**（切换后新 bootstrap 不复用旧账号未完成的探针）；settle/reset 时按 promise 身份清理。**单一机制**——去掉 v3.2 冗余的「request-sequence latest-wins」（gen 分区 single-flight + store gen-guard 已足够）。
（桌面 `onDisconnect` 重探与 §5.3 的 **web SSE 401 失活**是同一 `onDisconnect` 回调里的两分支，固定顺序见 §5.3。）

### 2.5 测试
`SyncStatusBar.test`：本地/连接中/未连接三态标签 + aria；`sync-status.test`：fetch 失败→`unreachable`、hello→重探、**并发探针按 `{gen}` 分区 single-flight（旧 gen 结果不落地）**；`subscribeSse.test`：`onDisconnect` 在 **error / 正常 EOF / 无 body / abort** 四类下各正确触发/不触发。**不改 daemon/`SyncState` union/类型。**

- **不手搓 outbox**：走 `updateNote` 正常路径生成 `sync_changes`。**本轮零 migration（D5）**。

### 3.4 ⭐ resolve 正确性 / 并发 / 陈旧快照 / 统一返回语义（v3.1 修 P1-1/P1-2/事务所有权）
**事务唯一所有者 = core `resolveConflict()`**（review 建议）：core 持整个外层 `sqlite.transaction`；daemon 只在**事务外**把 typed result/error 映射 HTTP + emit，杜绝 core/daemon 互相以为对方回滚。

**纯校验先于事务**（无 db，请求形状错 = 400 `VALIDATION`）：`strategy∈{local,merged}`；`strategy==='merged'` → `typeof content==='string'`（**空串合法**）；**`expected_updated_at_ms`：`typeof==='number' && Number.isFinite && Number.isSafeInteger && >=0`**（string/null/负/非整 → 400，**不**落到 CAS 变 409）。**错误码固定**：请求形状 400 `VALIDATION`；`UnsupportedEntity` 422 `UNSUPPORTED_ENTITY`；`BadPayload` 422 `BAD_PAYLOAD`；stale 409 `VERSION_MISMATCH`；trash 409 `ALREADY_TRASHED`；conflict 不存在 404 `CONFLICT_NOT_FOUND`、note 不存在 404 `NOTE_NOT_FOUND`。

**core `resolveConflict(db, sqlite, id, {strategy, content, expectedUpdatedAtMs})` 用 `sqlite.transaction(fn).immediate()`（P2-b：写事务，避免 deferred 在 SELECT 后升写锁得 `SQLITE_BUSY_SNAPSHOT` 而非 `changes===0`；内层 `updateNote` 退化 SAVEPOINT，异常仍一路回滚外层抢占）。顺序关键（P1-1：抢占先于写笔记）**：
1. **SELECT 冲突行**：无行 → **throw `ConflictNotFound`**（→404 `CONFLICT_NOT_FOUND`）；`resolved_at != null` → **`return {resolved:false, reason:'already_resolved'}`**（**此刻尚未写任何东西**，提交=空操作，正确）。
2. **⭐ 校验 entity + 确定最终内容（抢占前，不能丢内容来源）**：
   - **先统一断言 `row.entity_type==='note'`（不分策略——防未来 folder/conversation 冲突走 `merged` 绕过检查、把 `entity_id` 当 note id 更新）** → 否则 throw `UnsupportedEntity`（→422 `UNSUPPORTED_ENTITY`）。
   - `strategy==='local'`：`JSON.parse(row.local_payload)`（**异常 → throw `BadPayload`→422 `BAD_PAYLOAD`**）→ 取 `content`、校验 string（否则 `BadPayload`）。
   - `strategy==='merged'`：`content` = 请求 content（已过 §3.4 顶部纯校验，空串合法）。
3. **原子抢占（写笔记之前！）**：`UPDATE conflict_record SET resolved_at=?, resolution=? WHERE id=? AND resolved_at IS NULL`；`changes===0`（SELECT 与此间被并发抢先）→ **`return {resolved:false, reason:'already_resolved'}`**（仍未写笔记，空操作提交）。
4. **写笔记（CAS + 拒 trash，全部 throw 以回滚抢占）**：`updateNote(db, sqlite, row.entity_id, {content}, {expectedUpdatedAt: expectedUpdatedAtMs, rejectIfTrashed: true})`：
   - 返回 null（note 不存在）→ **throw `NoteNotFound`**（→404 `NOTE_NOT_FOUND`）；
   - **`AlreadyTrashedError`**（P2-c 复用，§3.3）→ throw（→409）；
   - `VersionMismatchError`（当前 ms ≠ expected）→ throw（→**409 stale**「笔记已变化，请重新加载冲突」）。
   > **关键**：步骤 4 的任何错误必须**抛出到事务外**，使 better-sqlite3 回滚**包括步骤 3 的抢占**——否则抢占已提交但笔记没改，冲突被错误标记为已解决。
5. **成功** → `return {resolved:true, note:<updatedNote>}`。
6. **daemon（事务外）**：`{resolved:true}` → **200** + emit `conflicts:changed`；`{resolved:false}` → **200**（不 emit）；throw 映射 404/409/422。
7. **GUI 刷新**：`bumpNotes()` + 用返回 note 刷新受影响笔记（**不只 conflicts:changed**）。
8. **open/dirty tab（D9）**：resolve 前该 note 有 **dirty tab** → 阻止+提示先保存/放弃；resolve 后有 **clean tab** → 用返回 note 刷新其 content + save baseline（防旧 tab 反向覆盖）。

## 4. ③ 会话隔离原语（L）— generation guard + invalidate/activate + bootstrap 协调器

### 4.1 必须复刻 `location.reload()` 的四件事
`MainApp.tsx:276-279` 现 `onProfileSwitched → location.reload()`，一次性保证：① 清全部 module store；② 挡所有在途异步写回；③ 重置 React 树/router；④ 断旧 SSE。逐条复刻如下。

### 4.2 ② generation guard —— 挡所有异步写回（v3 大幅扩范围）
**世代真源**：新 `stores/session-epoch.ts`（zustand）：
```
{ epoch:number, phase:'active'|'bootstrapping',
  beginInvalidate():number, beginBootstrap():number, endBootstrap(gen), setPhase() }
```
可 hook 订阅（驱动渲染）+ `.getState()` 同步读（异步守卫）。

**统一 helper（避免几十处手写 `if(epoch!==gen)`，review 指出维护坑）**：
```ts
export const currentGen = () => useSessionEpoch.getState().epoch;
export const isStale = (gen: number) => useSessionEpoch.getState().epoch !== gen;
/** 捕获 gen → await → 陈旧则丢弃 commit（覆盖最常见「取数后 set」形状）。 */
export async function guarded<T>(work: () => Promise<T>, commit: (v: T) => void) {
  const gen = currentGen();
  const v = await work();
  if (!isStale(gen)) commit(v);
}
```
多 await / 多 set 的动作：动作起点 `const gen = currentGen()`，**每个 await 后的副作用前** `if (isStale(gen)) return;`。

**覆盖范围 = 所有异步写回（不止 GET，review 指出）**：
- **GET fetch**：note/folder/tag/reminder/browser/config/conflicts/sync-status。
- **Mutations（post-await 有副作用）**：config 的 ~11 patch/reset；folder create/rename/move/remove/reorder（+`bumpFolders`）；note create（+`bumpNotes`）；editor save / **W7 resolve**（+baseline+`bumpNotes`）；AI send(stream)/approve-apply/delete（+`loadConversations`）；`performDelete`（+closeTab+`bumpNotes`）。
- **非 set 副作用**：`bumpNotes/bumpFolders/bumpConflicts`（data-bus）、CSS 变量写、快捷键注册、editor DOM 操作——**同样守卫**。
- **AI 流**（`ai-store.ts:304-357`）：`onEvent` set、`catch` patch、**`finally` set + `loadConversations()`**（abort 后仍跑 `:356`）全守卫；加 `abortAllStreams()`。
- **note-id-refs 特殊竞态（review 指出）**：`runFetch` 的 `finally` `pending.delete(id)` 可能删掉**新 generation 同 id** 的 pending Promise → 改为**按 Promise 身份删**：`finally { if (pending.get(id) === promise) pending.delete(id); }`；`cacheSet` 亦守卫。加 `resetNoteIdCaches()`（非 test-only）。

**审计清单**：见文末 **附录 A**（逐一列出所有 async store action → 守卫点），实施时对照打勾，避免漏项。
**测试关键**：epoch=N 起的 fetch/mutation/stream，在 `bump` 到 N+1 后 resolve → 断言**零 store 写、零 bus bump**。

### 4.3 ① reset —— 按类别列，不按数字（review 指出计数不准）
新 `stores/reset.ts` `resetAllStores()`：
- **11 个 zustand store（重置）**：`folder / config / reminder / conflicts / note / tag / sync-status / browser / ai / editor / pendingDelete`。各加 `reset()` + 清副作用（`sync-status` 清 `pendingTimer`+`probeStatus→pending`；`ai` `abortAllStreams`；`editor` 丢 tab/dirty/baseline）。
- **1 个 module 级 cache（重置）**：`note-id-refs`（`resetNoteIdCaches()` 清 `cache`+`pending`）。
- **不重置**：`data-bus`（zustand，但**保持单调**，归零会破坏不变量+中途触发请求，review 指出）；`session-epoch`（协调器自身，不重置）。

### 4.4 ④ SSE + ③ React 树/router —— `epoch`-keyed 重挂
- **epoch 是 external store**（module counter 不触发渲染，review 指出）→ `useSessionEpoch(s=>s.epoch)`。
- `key={epoch}` 挂**会话根**（D6：含 `EventsSubscriber`/SSE + 路由内容，**不含** transport 配置层）→ 卸载重挂：丢组件 local state + 断旧 SSE + 新 SSE 按新 profile 重订。
- **HashRouter 不自动回首页**（`MainApp.tsx:317` 重挂仍读当前 hash，review 指出）→ 重挂后**显式 `navigate('/',{replace:true})`**（或重挂前置 `window.location.hash='#/'`）。
- **⭐ SSE handler 也要 gen guard（P1-4，不能只靠卸载断流）**：epoch bump 到 effect cleanup/`AbortController` 生效之间有窗口，且**已排队的 `handleDaemonEvent` 会继续跑**（`open_note`→`openNoteById`→`navigate`、`conflicts:changed`→`refreshConflicts`→`bumpConflicts`、`sync:status_changed`→`setSyncStatus` 都含 await/写回）。→ **`EventsSubscriber` 订阅创建时捕获 `gen=currentGen()`**，传进 handlers；每个 handler 在**同步入口 + 每个 await 之后**各 `if (isStale(gen)) return;`。这样旧代订阅即使晚一拍触发也不写新代。

### 4.5 ⭐ bootstrap 协调器（v3 新增，修 review「无可等待协调器」）
现冷启动 fetch 散在 MainApp/EventsSubscriber/NoteList/FolderPanel 多个 effect，无法知道何时完成。**改为单一可等待入口，且用真实方法名**（P1-3 修正：`note-store` 是 `fetchNotes` 非 `fetch`；`folder-store` 有 `fetch`[树]+`fetchPanelNotes`[面板]两者；还漏了 config 后的 editor/browser hydration）：
```ts
async function bootstrapSession(gen: number) {
  await Promise.allSettled([
    useConfigStore.getState().fetch().then(() => {           // config + 派生 hydration（复刻现 MainApp:252-262）
      const { editor, browser } = useConfigStore.getState();
      if (isStale(gen)) return;
      useEditorStore.getState().setMode(editor.default_mode);
      useBrowserStore.getState().setSortKey(
        `${browser.default_sort_field}_${browser.default_sort_direction}`);
    }),
    useFolderStore.getState().fetch(),            // 文件夹树
    useFolderStore.getState().fetchPanelNotes(),  // 面板笔记
    useNoteStore.getState().fetchNotes(),         // 首屏列表（真名）
    useConflictsStore.getState().refresh(),
    useSyncStatus.getState().fetch(),
  ]);
  if (useSessionEpoch.getState().epoch === gen) endBootstrap(gen);   // 仍本代才落幕
}
```
**必须删/改原 mount fetch，否则「唯一入口」仍重复请求**（P1-3）：MainApp 的 `config.fetch`+hydration（`:252`）与 `conflicts.refresh`（`:267`）搬进 `bootstrapSession`；`NoteList`/`FolderPanel` 若在 mount 各自 fetch，改为**只读 store**（cold-start 由 bootstrap 拉）。注意 `note-store:70` / `folder-store:213` 的 **module 级 `useDataBus.subscribe` 自动重拉仍在**（data-bus 单调不 reset、reset 期不 bump，故不会误触发）。
保证（逐条对齐 review）：
- **coordinator + overlay 仅在 `startupMode==='normal'` 分支（P1-3，不能盖住迁移界面）**：`<App>` **先按 `startupMode` 分支**——非 normal（迁移）→ 直接 `<MigrationDialog>`（**不挂 Overlay/Coordinator**，否则 `bootstrapping` overlay 永久盖住迁移界面、且 Coordinator 会去访问未启动的 daemon）；`normal` → `<NormalSessionShell>` = `<SessionCoordinator/>` + `<BootstrapOverlay/>`（读 `phase==='bootstrapping'`）+ `<SessionRoot key={epoch}>`。后三者在 key 外 → 不随重挂卸载/循环。
- **⭐ 首次启动 bootstrap 入口 + overlay 一定收尾（P1-1；v3.3 强化）**：`SessionCoordinator` 在 key 外挂一次，**且是唯一探针所有者**（`WebAuthGate` 只按 `getWebSession()` 渲染 login/MainApp，**不自己跑探针**——消除「两处各自 activate → 双 bump/reset」）。
    - **桌面 normal startup**：`await bootstrapSession(0)`（**它自行 `endBootstrap(gen)`**，不再 `finally` 重复调——唯一所有权；初始 `epoch=0`/`phase='bootstrapping'`，**不 bump、不 reset**——stores 本就初始空，避免「启动即重挂」循环）。
    - **web**：`try { 读 sessionStorage token → 无 → return; 置 probingToken → GET /auth/session → 200 → activateWebSession(session,{persist:true}); 401/错误 → clearWebSession() } finally { endBootstrap(0) }`。
    - **⭐ overlay 一定落幕（修 v3.2：web 无 token / 坏 storage / 探针 401 时 `endBootstrap(0)` 从不被调 → BootstrapOverlay 永久盖住登录页）**：**web 分支**所有无 session 终态在 `finally` 调 `endBootstrap(0)` → 露出登录屏（桌面 + 成功 activation 由 `bootstrapSession` 自行收尾，避免重复所有权）。成功 activation 已 `beginBootstrap` 把 `epoch` 推到 1 → `finally` 的 `endBootstrap(0)` 因 `epoch!==0` **自然 no-op**。
    - **StrictMode 去重用 coordinator 内 `useRef` ran-once（或可重置 single-flight），非永久模块级 `ran-once`**（避免 HMR / 多 React root / 测试隔离踩坑）。
- **`beginBootstrap()` 原子完成 `epoch+1` 且 `phase='bootstrapping'`**（单个 `set`）。
- **落幕再比 generation**：`endBootstrap(gen)` 仅当 `epoch===gen` 才 `phase='active'`——**旧 bootstrap 不得关新 bootstrap 的 overlay**。
- **并发 401/activate 合并/幂等**：每次 begin 都 `epoch++`；旧 `bootstrapSession` 的 `Promise.allSettled` resolve 时 gen 已过期 → no-op。web 端 `onUnauthorized({usedToken})` 用 `usedToken===getWebSession()?.token` 比对去重（**不比 `getWebToken()`**——它含 `probingToken`，会让复水探针 401 被全局 handler 抢占清除、而非交 `SessionCoordinator` 收尾，§5.3）。
- **免闪烁**：overlay 覆盖「清空→重填」窗口，既无 `reload` 白屏、也无「空 store 闪」。

### 4.6 ⭐ 会话生命周期动作（v3.2：清理单一所有者 + web 唯一激活入口）
**`resetAllStores()` 是清理的唯一所有者**（doc-drift 修正）：它内部就调 `abortAllStreams()` + `resetNoteIdCaches()` + 11 store `reset()`；下列动作**只调 `resetAllStores()`**，不再各自重复调，避免两处维护。
```
invalidateSession():                       // 清，不 fetch、不 bootstrap（web logout / 401）
  beginInvalidate()                        // 原子: epoch++, phase='active'
  resetAllStores()                         // 内含 abortAllStreams + resetNoteIdCaches
  // MainApp 被 WebAuthGate 卸载回登录屏，无需 bootstrap

activateSession():                         // 桌面 profile 切换完成（daemon 侧已换库）
  const gen = beginBootstrap()             // 原子: epoch++, phase='bootstrapping'
  resetAllStores()
  // key 变 → 会话根重挂 → navigate('/',{replace}) → await bootstrapSession(gen)
  await bootstrapSession(gen)

activateWebSession(session, {persist}):    // ⭐ web 唯一激活入口（P1-2）：登录 + 复水共用
  const gen = beginBootstrap()             // 原子: epoch++, phase='bootstrapping'
  resetAllStores()
  setWebSession(session, {persist})        // 先发布 → 提供 bearer → WebAuthGate 挂 MainApp(keyed)
  await bootstrapSession(gen)              // 此时请求已带 token
```
- **桌面**：normal startup（`SessionCoordinator` 首次 bootstrap，§4.5）+ `onProfileSwitched` → `activateSession()`（后者替 `location.reload()`）。
- **web**：logout / REST-或-SSE 401 → `invalidateSession()`；**每次 unauth→auth（登录成功 / 探针 200）→ `activateWebSession(session, {persist})`**（登录 `persist=remember`、探针 `persist=true`）。
- **为何拆 invalidate/activate + web 单入口**：混一个 `resetSession` 会让 web logout 后 bootstrap 无处触发或 401 循环；且 §5.2 探针、§5.4 adapter 各自 `setWebSession` **无法保证「begin/reset → publish → bootstrap」顺序**（P1-2）→ 统一由 `activateWebSession` 内部保证。

## 5. ④ web session UX（M）— ✅ 完成（2026-07-22）

### 5.1 现状 & 缺口
- `web-session.ts` token 仅内存；`clearWebSession`（`:47`）**内存空即 early-return** → 持久化后坏 token 无限复水（review）。
- `GET /auth/session`（`auth.ts:106`）要 bearer；`WebAuthGate`（`:18-19`）session=null 只卸 `MainApp`，module store 不消失 → 跨账号残留。
- `LoginAndOpenSessionInput`（`types.ts:19-22`）**无 `remember`** → 类型缺口，修法见 §5.4。
- SSE 401 抛 `SseHttpError`，**不经** REST `onUnauthorized`（`sse.ts:204,223`）；且 `onError` **只在 `connectOnce` 抛错时触发**——正常 EOF / 无 body 会静默重连 → 需 exactly-once `onDisconnect`（P2-a，见 §2.4/§5.3）。

### 5.2 ⭐ `probingToken` 复水（v3 修 review「token-only 缺内存状态」）
只持久化 token（D7 token-only），但 `WebSession` 必含 identity+expiry → 复水期需一个不完整的过渡态：
```ts
let current: WebSession | null = null;
let probingToken: string | null = null;                 // 复水期临时 bearer
export const getWebToken = () => current?.token ?? probingToken;   // transport 读它
```
- **探针（`SessionCoordinator` 执行，§4.5；D8 = `WebAuthGate` 展示 loading 态）**：流程：读 `sessionStorage` token → 置 `probingToken` → `GET /auth/session`（transport 自动带 `probingToken`）→ **200 才 `activateWebSession(完整 session, {persist:true})`**（§4.6 内部 begin/reset→publish→bootstrap）并清 `probingToken`；**401 → 清 `probingToken` + `clearWebSession()`**（复水探针 401 由 Coordinator 自行收尾，**不经全局 REST handler**——§5.3 只比 `getWebSession()?.token`，此时仍 null）；无 token → 直接登录屏。**绝不构造假 identity。**
- **`probeInflight` 生命周期约束（P2-6，StrictMode 去重 + 防旧探针覆盖）**：`probeInflight` **按发起 token 绑定**（`{token, promise}`）；`finally` 中**仅当仍是同一 promise 才清**（`if (probeInflight?.promise === p) probeInflight = null`）；**发布 session 前再确认 `probingToken === 发起时 token`**——否则 (a) 失败 promise 被永久复用，(b) 旧探针晚到覆盖更新的会话。
- **`clearWebSession` 修正**：**无条件** `try{ sessionStorage.removeItem(KEY) }catch{}`（即使内存空）+ 清 `current`/`probingToken` + emit。坏 JSON/读异常 → 视为无 session + 清 storage。

### 5.3 接入 ③ + SSE 401 / onDisconnect 恢复（均按订阅世代 + 请求 token 守卫）
- **每次 unauth→auth（登录成功 / 探针 200）→ `activateWebSession(session,{persist})`**（P1-5）：只比 `lastLoadedProfileId` 不够——logout/invalidate 后**重登同一账号** `profile_id` 没变但 stores 已清空、无人重填 → 必须无条件 activate。顺序由 `activateWebSession` 内部保证（§4.6）。
- **logout**：`clearWebSession(); invalidateSession();`。
- **⭐ REST 401 按「请求实际所用 token」比对（P1-2；v3.3）**：generation guard 挡不住 transport 内部的 `onUnauthorized`——旧账号 A 的请求若在账号 B 发布**之后**才 401，`onUnauthorized()` 里 `getWebSession()` 已是 B → 误清 B。→ **改 transport 契约**：`request()` 发请求时从认证源记录**裸 token**，401 时回调 `onUnauthorized({usedToken})`（**传裸 token，不是 `"Bearer …"` 头**——否则与返回裸 token 的比较永不相等）；web 处理器 `if (usedToken === getWebSession()?.token) { clearWebSession(); invalidateSession(); }`。**必须比 `getWebSession()?.token`、不是 `getWebToken()`**——后者含 `probingToken`，会让复水探针 401 被全局 handler 抢先 invalidate（应由 `SessionCoordinator` 收尾）。A 的迟到 401 因 `usedToken!==B` 被忽略。测试：「A 请求 → 激活 B → A 迟到 401 → B 保留」。**④ 的 shared 触及含 transport 契约**（不只 login 类型）。
- **⭐ SSE `onDisconnect({error, clean, usedToken})` 固定顺序处理（P1-5/P2-a，不能只看帧）**：`subscribeSse` **订阅创建时捕获 `gen=currentGen()`**（`usedToken` 由回调按每次 `connectOnce` 携带，§2.4）。顺序：**① `if (isStale(gen)) return;` → ② 当前 session 的 401（`error instanceof SseHttpError && error.status===401 && usedToken===getWebSession()?.token`）→ `clearWebSession(); invalidateSession(); return;` → ③ 其余 disconnect → `useSyncStatus.getState().fetch()` 重探**。②先于③ = **401 后不再发无 token 的状态探针**；`usedToken===getWebSession()?.token`（非 `getWebToken()`）= 旧订阅/旧账号迟到 401 不踢新账号。

### 5.4 「记住我」plumbing + 类型
- **类型（review 修正）**：给 `LoginAndOpenSessionInput`（shared/owl-api）加**可选 `remember?: boolean`**（桌面忽略）；**`LoginFormValues` 显式 `extends LoginAndOpenSessionInput`**（独立接口不会自动继承 `remember`）。

## 附录 A — generation-guard 审计清单（③ 实施对照打勾）
> 原则：**任何「await API → 写全局 store/bus / DOM·CSS·快捷键副作用」的路径**（store action、模块函数、组件单-/多-await handler、定时器）都要 `if (isStale(gen)) return;`（或用 `guarded`）。

| tag-store | `fetch` | set 前 |
| reminder-store | `fetch` / CRUD | set 前 |
| browser-store | 列表 fetch | set 前 |
| config-store | `fetch` + ~11 patch/reset | 各 set 前 |
| conflicts-store | `refresh` / `refreshList` / **resolve 后刷新** | set 前 |
| sync-status | `fetch` | set 前；**single-flight 按 `{gen,promise}` 分区**（P2-a） |
| editor-store | save / **W7 resolve baseline** | set + `bumpNotes` 前 |
| ai-store | send(stream `onEvent`/`catch`/`finally`) / approve-apply / delete | 各 set + `loadConversations` 前；`abortAllStreams` |
| DeleteConfirm | `performDelete` | closeTab + `bumpNotes` 前 |
| note-id-refs | `runFetch` | `cacheSet` 前守卫；`finally` 按 Promise 身份删 pending |

| **SSE 订阅**（P1-4/P1-5，**订阅≠免疫**） | `EventsSubscriber` 的 `onEvent`(`open_note`→navigate / `sync:status_changed` / `conflicts:changed`)、`hello`、**exactly-once `onDisconnect({error,clean,usedToken})`**（唯一断线回调，替代 `onError`） | **订阅创建时捕获 gen**（`usedToken` 按每次 `connectOnce` 携带）；每个回调**同步入口 + 每个 await 后**先 `isStale(gen)`；`onDisconnect` 顺序 = stale→return / 当前 session 401→clear+invalidate+return / 其余→fetch status。epoch bump 到 cleanup/abort 有窗口 + 已排队帧续跑 → **不能只靠卸载断流**。 |
