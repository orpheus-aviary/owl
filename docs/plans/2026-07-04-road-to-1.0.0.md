# owl 通往 1.0.0 的路线（road to 1.0.0）

> 状态：**规划定稿 2026-07-04**。这是 0.5.0 发版 + Phase A（云端 daemon 核心）+ Phase B（网页版 v1）+ Aω 1a（本地云 rig CSP 验证）**全部完成之后**、走向 1.0.0 的**唯一路线源**。
> **当前状态 + 已完成明细以 `PROCESS.md` 为准**；本doc 只管「往后怎么走」的顺序与范围。
> 取代/更新以下旧表述（见文末 §5 对账）：把 **Aω 当一坨「发 owl-server + 上云」**、**响应式「不做」**、**跨 profile 视图排进 0.6**、**dev-flow B→C→D→E 无 1.0.0 关卡**。

---

## 0. 前情（一句话）

owl 0.5.0（per-profile 隔离 + 免密快切）已公开发版；扩生态 Step 0 + Phase A 核心（A0–A5）+ Phase B 网页版 v1（B0–B4）+ **Aω 1a 本地云 rig（登录后内容在严格 CSP 下全部正常）** 均已完成并 push。往后就是本doc 的两阶段 + 1.0.0 后。

---

## 1. 本轮（2026-07-04）拍板的决策

1. **两阶段重排（ship-first）**：把「不碰真服务器就能做完的」全部先做完（Stage 1，含 **owl-server 本地打包**），再把「公网部署 + TLS + soak + 多设备 GA」攒成**发版前最后一道关卡**（Stage 2）。动机：只搭一次云、把不确定性最大的真公网/长时/多设备压成一次集中彩排，避免反复搭/拆阿里云 skybridge。
2. **Aω 一分为二**：**Stage 1 = owl-server 本地打包 + 本地 rig 跑通**（早暴露打包/ABI/端口风险，只差公网）；**Stage 2 = 上云 + 异地真机**。
3. **顺序微调**：**重构一轮提前到 0.6 功能之前**（0.6 计划本就把功能 gate 在系统性清理之后；且 W7/resetAllStores 要动的大文件先拆更干净）。
4. **跨 profile 视图 → 1.0.0 之后**（不着急，且统一视图机制完全空白、工程量最大）。跨账号导入时机再议。
5. **移动端 = 双轨并存、不冲突**：① 网页版加一份**移动端兼容 UI**（响应式 / 移动导航，属 **Stage 1**，发网页版前做）；② 之后仍单独做**完整 React Native app**（**1.0.0 之后**，Phase C 发 owl-shared → D/E）。两者只共享 `owl-shared` + 逻辑，视图各写一遍。**推翻旧「响应式不做 / 移动=RN-only / web=桌面浏览器优先」表述。**
6. **设计稿 just-in-time**：每个 item 临开工前才写它自己的子设计稿，不一次囤好几份放馊。
