## 修了什么

### 1. 同步游标互相清零（本轮的主角）

`sync_cursor` 的 pull 游标和 push 游标会互相冲掉：**每次本地写入之后，下一轮同步都会重新拉取
整条变更日志**。真机实测一天 49 轮全量重放、日志 6.5 MB。

没有数据损坏（重放的变更要么被自身回声识别、要么 LWW 判定跳过），但代价是流量、CPU、电量，
而且**随变更日志线性恶化** —— 日志越长，每次改一条笔记要重放的东西越多。

副作用还有两个：`GET /sync/status` 的 `pushed_seq` 永远显示 0（一直被当成「没实现」）；
0.6.2 的 outbox 裁剪在任何「推送过」的轮次里一行都删不掉，实际效果被随机腰斩。

根因是一条 SQL 里两个 `COALESCE` 打架，细节见计划 §2。修完之后：

- 每轮的起点等于上一轮的终点，正常增量只拉新变更；
- 两个游标同时单调推进，`pushed_seq` 不再是 0；
- 裁剪按预期工作。

> **升级后可能有一次偏长的同步**：如果升级时游标恰好停在被清零的状态，第一轮会做最后一次
> 全量重放然后自愈。看到一次长同步是预期的，不是没修好。

### 2. 同步日志现在说人话

以前每处理一条变更打一行 info（一天两万多条），却**没有任何一行描述整轮同步**。
上面那个 bug 能藏三周，直接原因就是这个：每一轮都写着「从 0 开始」，但没人看得见。

现在每轮成功同步输出一行 `sync round done`，带游标前后、拉取/应用/跳过/推送/重复的计数、
以及**是什么触发了这一轮**（SSE 变更 / 重连补拉 / 定时器 / 本地写入 / 手动）。
逐条变更的日志降到 debug，默认不再刷屏。

### 3. 置顶和排序现在能跨设备了

置顶（pin）和拖拽排序此前在接收端被直接丢弃 —— 也就是说**一台设备改了，另一台永远看不到**。
真机日志显示每天有几百次置顶、几千次排序变更被丢掉。

现在两者都会应用。它们不参与正文的冲突判定（按到达顺序生效，两台设备同时拖拽以后到服务器的
为准）—— 这是刻意的：给它们加时间戳会让一次置顶「压过」另一台设备的正文编辑并把它丢掉，
丢一次排序很便宜，丢一次编辑不便宜。置顶/排序也不会再让笔记看起来「被编辑过」。

> ⚠️ **只保证 0.6.3 之后新产生的置顶/排序**。升级前既有的状态不会自动对齐 ——
> 在**一台**设备上重新拖一遍 / 重新点一次置顶即可。

### 4. 云端「没人登录」现在会报警

owl-server 的登录凭据只存在内存里（服务器没有钥匙串，刷新令牌不落盘），所以**每次重启后
同步都会静默停摆，直到有人打开网页登录一次**。此前这个状态毫无提示：桌面端一切正常，
只有云端默默掉队 —— 2026-08-11 那次复盘就是这么发现云端漏升了两个版本。

现在云端无会话满 10 分钟会打一条警告，之后每小时一条；`GET /status` 也多了一小块同步健康信息
供外部监控轮询。它不会自动恢复（仍需人工登录一次），只是让这个状态可被发现。

## 升级

**桌面**：下载 dmg 覆盖安装。**CLI**：`npm i -g @orpheus-aviary/owl-cli@0.6.3`。

**云端**（fish，阿里云）：

```fish
cp -a /www/owl-nest/owl /www/owl-nest/owl.bak-(date +%Y%m%d)
cd /www/owl-server
npm install @orpheus-aviary/owl-server@latest --@orpheus-aviary:registry=https://registry.npmjs.org
grep -m1 version node_modules/@orpheus-aviary/owl-server/package.json
pm2 restart owl-server
```

**重启后必须从网页端登录一次**，否则云端不会恢复同步（见上面第 4 条）。自检：

```fish
curl -s http://127.0.0.1:47020/status | jq .data.sync
# {"session_installed": true, "state": "session_ready", "last_success_at": 1786...}
```

判活要 `state == "session_ready"` **且** `last_success_at` 在合理窗口内 —— 前者只说明会话装上了，
不代表 skybridge 可达或最近一轮同步成功。

三端共用同一套同步代码，**建议一起升**；本轮无 migration，所以不同步升也不会坏数据。
