# owl 0.6.1 — 编辑即同步 + 另一端自动刷新 (macOS arm64)

> 用户可见 release notes 草稿，供 GitHub Release body。macOS arm64 only。
> 数据目录 `~/orpheus-aviary-nest/owl/` 不动，可直接覆盖装。

0.6.0 真机长期使用后修的一批**跨设备同步**问题。核心是一句话：**以前「对方改了这边秒到，
自己改了要等很久」，现在两个方向都是秒级，而且界面会自己更新。**

## 编辑之后立刻同步出去

0.6.0 的同步只有三个触发点：收到别人的推送、定时器（默认 5 分钟，可配置甚至可关）、手动点。
**唯独没有「本地写完 → 推出去」**，所以自己的编辑要么等定时器，要么手动点一次，
而对方的编辑靠 SSE 秒到 —— 一边快一边慢。

0.6.1 补上这个触发器：本地笔记落库后**约 1–2 秒**自动推送。连续打字不会反复推
（停手 0.8 秒才发，最长 5 秒兜底），推失败按 2→4→8→16→30 秒退避重试，不会一直空转。

**覆盖 daemon 进程之外的写入**：`owl --direct` 直写、数据库迁移补写的记录，
在 daemon 下次启动后 2 秒内也会被推出去。

## 另一端界面自己刷新

以前同步到的新数据只落到本地库，**列表和编辑器要手动刷新才看得见**。现在：

- **笔记列表 / 回收站 / 文件夹树**自动刷新。
- **打开着但没改过的笔记**，内容自动更新成最新版本。
- **打开着且有未保存改动的笔记**：不会覆盖你正在写的东西，编辑区顶部出现一条提示
  「这条笔记在别处被修改过」，可以选择「加载远端（放弃本地改动）」或继续写。

## 修掉一个静默覆盖

桌面版此前保存时**不做版本检查**（只有网页版做）。同步把对方的编辑拉下来后，你在旧内容上
按 Cmd+S，会**不声不响地把对方的编辑盖掉**，并且这个覆盖还会同步出去把对方那边也盖掉。

0.6.1 桌面版也带上版本检查：这种情况现在会弹出版本冲突对话框
（**用我的版本覆盖 / 放弃本地，加载远端 / 取消**，可以看逐行 diff），由你来定。

## 随记 / 待办跨设备终于对了

随记、待办用固定 id、每台设备本地生成。此前生成时打的是**当前时间**，于是「今天刚开机的设备」
盖过「对方昨天的真实编辑」，导致对方写的随记内容永远同步不过来。

0.6.1 改成固定时间戳，任何一次真实编辑都能胜出。
**副作用**：从未编辑过的随记 / 待办在按时间排序的列表里会排到最底、日期显示 1970，
编辑一次之后恢复正常。

## 云端版：网络抖动不再被当成掉线

云端 owl-server 此前只要刷新 token 失败（**包括网络抖动、服务端 5xx**）就直接清空登录状态，
连带把所有浏览器会话踢掉。0.6.1 只有服务器明确判定凭据失效才登出；网络问题保留凭据并按
30 秒→5 分钟阶梯自动重试。同时访问令牌被拒时会自动刷新并重试一轮。

## 其它

- 无账号 / 未登录时，后台同步不再每次空转报错刷屏日志（此前一次会话里出现过 163 条）。
- 设备管理里的版本号不再固定显示 `owl 0.5.0`。
- 部署文档补上 skybridge **必须单实例 fork** 的说明（多副本会让 SSE 广播静默失效，
  症状和同步失灵一模一样但极难归因）。

## 仍留后续

- **token 过期后桌面自动恢复**：目前过期仍需在设置里手动重新登录一次。
- 附件跨设备传播 / TLS 反代 / 多设备 GA — 随后续版本。

## 安装 / 升级

### GUI

1. GitHub Releases 下载 `Owl-0.6.1-arm64.dmg`，拖入「应用程序」。
2. 首次打开（ad-hoc 签名）：右键 Owl.app → 打开 → 弹窗点「打开」；或系统设置 → 隐私与安全性 →
   「仍要打开」。之后不再询问。
3. 数据目录不动，首启自动跑 schema 迁移（本版含一个迁移，`user_version` 9 → 10）。

### CLI

**无改动，不用升级**（仍是 0.6.0）。

### 云端版 owl-server

```bash
npm i @orpheus-aviary/owl-server@0.6.1
```

⚠️ **跨设备同步的修复需要两端都升级**：桌面和 owl-server 跑的是同一套同步代码，
只升一边的话另一边仍是旧行为。
