# owl 0.6.2 — 登录过期自己修好 (macOS arm64)

> 用户可见 release notes 草稿，供 GitHub Release body。macOS arm64 only。
> 数据目录 `~/orpheus-aviary-nest/owl/` 不动，可直接覆盖装。

0.6.1 让两个方向的同步都变成秒级；0.6.2 处理的是**同步停下来之后的事**：登录凭据过期、
daemon 单独重启、token 被服务器拒绝 —— 这些以前都会让同步悄悄停住，界面还显示「离线」或
「已同步」，你不点一次「登录」就一直不同步。现在它自己修好。

## 登录过期自动恢复

新增一个明确的状态：**「需登录」**（状态栏红点）。以前这些情况全都伪装成别的样子：

| 情况 | 0.6.1 的表现 | 0.6.2 |
|---|---|---|
| access token 被服务器拒绝 | 「出错」，然后一直不同步 | 后台自动换新 token，状态栏最多闪一下「需登录」就回「已同步」 |
| daemon 单独重启（应用没关）| 「离线」，等下次手动同步 | 自动把凭据重新装回去，1 秒内恢复 |
| 长连接在建立时就被拒 | **无限「离线」+ 无限重连一个死 token** | 认出这是认证问题，停止重连并走恢复流程 |
| 设备被吊销 / 凭据彻底失效 | 一直显示「正在重试」 | **立刻**提示「登录已失效，请在 设置 → 同步 重新登录」 |

区别很实在：前三种**完全不需要你操作**，只有最后一种才需要你重新登录 ——
而且它会明确说出来，不会让你盯着一个永远转不完的圈。

状态栏悬停可以看到当前是哪一种：「正在自动恢复登录…」还是「登录已失效」。

## 冲突页能解释「为什么是它赢」

同一条笔记在两台设备同时改，谁赢由「修改时间 → 同一毫秒内的写入计数 → 设备 id」三级决定。
以前冲突页只显示时间戳，两边时间**一模一样**时就完全看不出所以然。

现在同毫秒的冲突会补上后两级：时间戳后面跟 `· #计数`，计数也相同时再加上设备，
并写明「同一毫秒 · 计数相同，由设备 id 定序」。0.6.2 之前记录的老冲突行显示不变。

## 同步日志不再无限膨胀

每次改笔记都会在本地记一行同步日志，此前**只增不删**。长期使用（尤其是 7×24 跑着的
云端服务）会一直堆积，占空间也拖慢启动时的统计。

0.6.2 起，已经确认送达、且服务器不可能再重发的记录，会在**同步成功后**顺手清掉一批
（每小时最多一次，只清 7 天前的）。四道安全闸任意一道不成立就整轮不清，
宁可留着也不冒丢数据的险 —— 清理只是省空间，绝不影响同步正确性。

## 升级注意

- **数据库有一次结构升级**（`user_version` 10 → 11，只加列不删数据），**单向不可回滚**。
  升级前建议备份 `~/orpheus-aviary-nest/owl/`。升级后不要再用 0.6.1 及更早的版本打开同一个库。
- **桌面 / CLI / 云端服务共用一套数据层，必须一起升**：
  桌面 dmg + `@orpheus-aviary/owl-server@0.6.2` + `owl-cli@0.6.2`。
  （顺带修掉 0.6.1 的遗留：当时 owl-cli 没跟着发，`owl --direct` 打不开升级后的库。）
- 首次打开会看到一次短暂的迁移，不需要任何操作。
