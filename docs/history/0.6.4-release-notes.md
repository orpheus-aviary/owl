# owl 0.6.4 发版说明（2026-08-27）

小版本。**无 migration**（`user_version` 仍 11），协议不变，可与 0.6.3 混用。

两件事都关于「设备」，起因是给 skybridge 做长期运维体检时顺出来的。

## 设备列表现在只显示 owl 的设备

设置 → 同步 → 管理我的设备。

同步账号下的设备是**按账号**注册的，所以 lark 的手机和桌面也在同一个列表里 —— 用得越久越乱。
现在只显示 owl 的（外加 app 信息未知的那些：无法证明它不是你的 owl，而这个列表正是你用来
「停用一台不再信任的设备」的地方，藏错方向比多显示更糟）。

被隐藏的会在列表底下说清楚：**另有几台属于同一账号的其它工具**。它们同样持有这个账号的凭证，
只是要停用得去那个工具里操作。

**已撤销的设备折叠起来**，展开后有一句说明：它们删不掉，因为同步记录里每条变更都记着是哪台设备
写的，删掉设备那些记录就说不清出处了。折叠里的设备不再显示「移除」按钮。

顺带一提：设备的「上次活跃」以前显示的其实是**注册时间**（服务端只在注册时写过一次）。云端 skybridge
升到 0.1.5 之后这一行就变准确了，owl 这边不用改。

## 设备被移出账号后，重新登录能恢复了

以前如果你在别的设备上把这台 owl 移出了账号，这台 owl 会卡死：登录**看起来是成功的**，但之后
每一次同步都失败，而且**退出重登也救不回来** —— 它一直在用那个已经作废的设备身份。

现在登录时会先问服务器「我记着的这台设备还算数吗」，答案是否定的就重新注册一台，同步随即恢复。
同步页面上那句错误提示也改成了可操作的：「这台设备已被移出该账号，请退出登录后重新登录」。

重新注册会在账号里留下一行新设备记录（旧的那条撤销记录删不掉，原因同上）。这是有意的 ——
把你刚刚关掉的那扇门用同一把钥匙再打开，不是恢复该有的样子。

## 升级

- 桌面：下载 `Owl-0.6.4-arm64.dmg` 覆盖安装。
- 云端：`npm install @orpheus-aviary/owl-server@latest` + 重启进程，**重启后需要从网页端登录一次**
  （云端凭据只在内存里）。
- CLI：`npm i -g @orpheus-aviary/owl-cli@latest`。

三端可以不同步升级，本版没有 migration 也没有协议改动。
